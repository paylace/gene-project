## 1. 범위와 변경 내용

완료한 실험 코드를 수정하지 않고 공통 기반·실험 어댑터·명시적인 실행 프로필을 추가했다. 동결된 초기 분포·유전 연산·지표·동률 규칙을 재사용한다. 기존 기록에서 유리한 개체를 선발하거나 본 성능 판정을 다시 하지 않았다. 모든 새 정책 입력은 훈련 분할이며 본/실제 검증/테스트 분할 호출은0이다.

평가에서는 같은 그래프의 후보들을 함께 처리하고, 간선 순서와 float64 합산 순서를 유지했다. 동률이 있을 때만 기존 키의 난수 객체를 준비한다. 지원되지 않는 그래프는 명시적인 기준 콜백을 쓴다. 후보별 상태·난수를 섞지 않는다. 기존 평가와 전체 기록·실제 지표·행동·동률 수가 같아야 채택했다.

저장은 두 방식을 구현·비교했다. 첫 버전은 행동을 재생해 결과를 복원하고 관측 예외를 보존한다. 비용이 커 후속 버전에서는 관측된 정수·불리언 열을 직접 압축했다. 모르는 필드, 누락, 타입 차이, 잘못된 실제 보상과 행동도 보존한다. 원본 전체 JSON과 내용 해시를 확인하며 기록을 정상 값으로 몰래 바꾸지 않는다.

## 2. 코드 구조·재사용성·확장성 평가

| 항목 | 구현·검증 근거 | 남은 한계 |
|---|---|---|
| 평가와 실험 분리 | 공통 집단 평가에 지표·기준 평가 콜백 주입. 어댑터는 동결 유전 연산·지표를 import | 현재 고정4모듈 tanh와 이동·수집에 최적화. 범용 학습 엔진 아님 |
| 저장 재사용 | 공통 원자 Store를 원래 JSON·재생 codec·관측 열 codec이 함께 사용 | 파일 단위 객체를 구성하며 무한 스트리밍 형식은 아님 |
| 구조 확장 | `auto` 미지원 그래프의 기준 경로와 강제 고정 경로의 거부를 검사 | 모든 새 구조에 대해 자동으로 빠른 경로를 만들지는 않음 |
| 기록 확장 | 새 필드·희소 필드·큰 정수·bool/int/float 차이·잘못된 관측을 왕복 검사 | 임의의 Python 객체를 JSON 증거로 저장하는 기능은 없음 |
| 운영 보존 | 임시 쓰기·fsync·원자 게시/교체, 완료 덮어쓰기 거부, 코드/내용 해시·회차 원장 | 모든 네트워크 파일시스템 장애 내구성과 동시 스레드 계수는 미검증 |
| 사용 경로 | [단일 프로필 API](../../studies/interaction/experiment_runtime_v01.py)에서 reference/balanced/archive 조합 | 현재 훈련 전용 기술 API. 본 접근/잠금/분석 실행기 통합 전 |

실험별 네트워크·유전 연산을 새 패키지로 통째로 복사하지 않았다. 평가 커널을 바꾸지 않고 저장 codec만 다른 버전에서 재사용했다. 다만 검사·버전 보존을 포함해 새 코드가 추가됐으므로 전체 저장소 코드 줄 수 감소를 주장하지 않는다. 과거 패키지와 동결 의존 관계도 남아 있다.

## 3. 평가 속도와 결과 동치

기술 시드3101/3102를 미리 지정하고 집단20/40, 훈련24개×1반복/훈련252개×3반복을 기준·최적화 경로 각각3회 측정했다. 각 실행은 별도 프로세스다. 목적 문자열·초기화·순서는 동일하며 결과 전체 해시가 모든 대응 실행에서 일치했다. 저장 비용은 이 표에서 제외하고 아래 통합 표에서 별도 확인했다.

| 집단·에피소드 | 기준 초 | 집단 평가 초 | 속도 배수 |
|---|---:|---:|---:|
| 20×24 | 0.075575 | 0.013818 | 5.47배 |
| 40×24 | 0.151394 | 0.020506 | 7.38배 |
| 20×252×3 | 0.418985 | 0.179876 | 2.33배 |
| 40×252×3 | 0.829089 | 0.375280 | 2.21배 |

시간은3회 중앙값이고 개별 값은 원자료에 있다. 큰 사례의 최대 프로세스 working set은 기준 약68.46MiB·최적화 약69.87MiB로 메모리 감소를 보장하는 개선은 아니다. 큰 배열의 동시 처리 비용이 있다. 운영체제 캐시는 통제하지 않았다.

계수기의 `rng_objects_created`는 **새 지연 난수 경로만 계측**한다. 기준 경로에 기록된0은 기준이 난수 객체를 생성하지 않았다는 뜻이 아니다. 동결 기준 코드는 에피소드마다 객체를 준비하며, 그 수는 호출 수로 산술 계산할 수 있다. 이 계수 범위 한계를 원자료를 소급 수정하지 않고 명시한다. 동률 fixture에서는 실제 추첨 결과와 동률 수를 기준 경로와 비교했다.

## 4. 로그 크기와 처리 비용

각 버전 안에서3회 중앙값을 사용했다. 서로 다른 시간대의 측정을 같은 통제 시행으로 취급하지 않는다. fsync와 원본 검증을 포함하며 JSON 압축 비용만 비교한 값이 아니다.

첫 재생형은 작지만 쓰기/복원 비용이 커 실행용 기본값으로 채택하지 않았다. 후속 관측 열은 약169KB 더 크지만 환경을 재생하지 않아 복원이 빠르고 기록 자체를 환경 코드 없이 복원한다. Q1-010의 약1.211MB 형식은 정상 필드의 재구성을 전제로 했으나, 이번 재생형은 관측 예외와 새 필드를 보존하는 일반 경로여서 크기·구현 비용이 다르다. 예전 값을 새 방식의 성적으로 쓰지 않았다.

변경하지 않은150파일·1,216,905바이트까지 포함하면 관측 열 gzip9의 대체 폴더는2,606,178바이트로 기존4,355,420바이트 대비40.16% 축소에 해당한다. 실제 원본은 보존했고 사본 비교만 수행했다. 모든 정보를 담는 절대 최소 바이트를 증명한 결과는 아니다.

## 5. 통합 경로 — 평가부터 실제 저장·복원 검증까지

후속 계획에 따라 `ExperimentRuntime`에서 기준 평가+JSON gzip3과 묶음 평가+관측 열 gzip9를 실제 조합했다. 파일에 쓴 뒤 읽고 복원한 전체 결과가 모든 대응 조건에서 같았다. 보관 단계만 제외한 추정이 아닌 실제 통합 경로다. 다만 번식·프로세스 스케줄링·본 후보 잠금·전체 연구 감사까지 포함한 본 실행 시간은 아니다.

| 사례 | 반복/프로필 | 기준 전체 초 | balanced 전체 초 | 속도 배수 | 압축 파일 기준→balanced |
|---|---:|---:|---:|---:|---:|
| 20×24 훈련 | 3 | 0.091769 | 0.039301 | 2.34배 | 16,703→9,798바이트 |
| 40×24 훈련 | 3 | 0.184582 | 0.073504 | 2.51배 | 32,140→18,187바이트 |
| 20×252×3 훈련 분할 평가 | 2 | 0.605610 | 0.496039 | 1.22배 | 146,876→22,980바이트 |

큰 사례는 호출 상한을 지키기 위해 사전에2회만 정했다. 중앙값은 두 값의 중간이며 정밀한 시간 추정이나 통계적 우월성 검정이 아니다. 작은 사례와 큰 사례의 저장 압축률 차이는 기록의 반복성과 고유 행동열 비중이 다른 데 따른다. 본 로그 전체의 확정 축소율로 일반화하지 않는다.

## 6. 오류·검사·호출 원장

첫 개발 검사15개 중4개가 파일 게시 단계의 하드링크 권한 오류로 실패했다. 실패 소스·로그·요약을 `development_01`에 보존했다. 새 정책 완료438호출이고 미확정 상한0이다. Windows에서 기존 대상이 있으면 실패하는 rename으로 게시하도록 개발 단계에서 수정했다. 두 번째15검사는3,558호출로 통과했고 그 소스도 보존했다. 접근 차단·조기 성공 검사를 추가한 최종17검사는3,582호출로 통과했다. 관측 열의6검사는 정책 호출0으로 통과했다. 최종 검사 종류는17+6=23개이며 개발 실행의 누적 검사를 독립 확인 수로 부풀리지 않는다.

총 상한380,800 이내이며 별도 fixture에 배정한100,000 중 개발+통합은76,698이다. 실패나 재개를 제외하고 성공 값만 합산하지 않았다. 미확정 정책 호출 상한은0이다. 실제 검증·테스트 분할과 본/확인 실행은0이다. 네트워크 forward의 입력 배열 동치 검사와 환경 로그 재생은 별도 기술 작업이며 정책 에피소드 수에 합치지 않았다.

이 합계는 사전 계획에 따른 로컬 기술 실행이다. GitHub CI의 반복 검사·계승된 회귀 검사 호출은 별도이며 로컬 성능 측정 표본에 합치지 않는다.

## 7. 판단과 적용 범위

**기술용 기본 프로필은 balanced로 제안한다.** 평가를 빠르게 하고 모든 관측을 직접 보존하면서 실행·저장·복원 전체 비용도 줄였다. 더 작은 용량이 우선인 보관 작업에는 archive가 있지만 쓰기/복원 비용을 감수해야 한다. `reference`는 비교 기준으로 유지한다. 저장 단계를 하나의 최소 용량 옵션으로 강제하지 않았다.

재사용성은 공통 Store·평가 커널·기록 codec·실험 어댑터·단일 프로필 API의 분리로 확인했다. 확장성은 실제 미지원 구조와 새 필드의 처리로 일부 검증했으며, 아직 임의의 환경·순환 기억·생애 학습까지 최적화한 것은 아니다.

Q1-007의 본 실행기 통합,80시드 전체 비용 예측,본 후보 잠금·테스트 접근·확인 단계의 전 경로 검증은 다음 작업이다. 기존4시간/20GiB 비용 미통과를 이번 속도 배수만 곱해 통과로 바꾸지 않는다. 로그의 의미가 잘못된 경우를 보존하는 기능과, 그 의미를 검증하는 감사는 구분한다.
