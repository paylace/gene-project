## 1. 목적과 질문

고정4모듈 F0 안에서 집단20/40×100/200회차의 예산 배분과 확대를 비교할 계획이다. 본80짝 시드에서 검증 선발 후보의 테스트 완료율80% 이상 발견 비율을 주 지표로 둔다. PT−B 단측·P−T 양측의 정확 대응 이진 검정/Holm·10pp 기준은 기존 계획에 있다. 이번에 완료한 것은 이 본 실험을 시작할 구현·비용 조건이 충족되는지 확인하는 단계다.

Q1-006의 성능을 본 뒤 설계한 후속 연구이며 F0 우세를 확정해 채택한 것이 아니다. 본 성능 자료는 생성하지 않았다. 비용 미통과를 탐색 규모 효과 또는 지능 가능성에 대한 부정적 결과로 해석하지 않는다.

## 2. 구현과 준비 조건

새 패키지 `studies/interaction/evosim_q1007_v01/`를 만들고 완료한 Q1-006 v0.2 및 Q1-004 의존성은 변경하지 않았다. 고정 tanh4모듈·연결28개·모듈 편향4개로 탐색 수치 파라미터32개이며 출력 편향·기억·순환·생애 학습은 없다. R0/S0와 원래 좌표·유전 연산을 계승한다.

물리 실행 E20(20개체×200회차),E40(40×200),R20(무작위20×400)에서 일곱 끝점 후보를 분리한다.100회차 후보는 그때까지의 검증 후보만 포함한다. 검증은1기준10,20,…회차에 전 개체를 평가하고0회차에는 없다. P/T의 총검증 후보는400개씩이다. 이 일정은 Q1-006과 달라 과거 B의 완전 복제라고 부르지 않는다.

이번 공식 예비는 시드2901·2902에서 E20/E40/R20의6작업을 각각20회차 실행했다.7회차 중단 뒤 원자 체크포인트·난수 상태로 재개했다. 매 회차 훈련 에피소드24개, 검증·테스트 호출0으로 총76,800호출이다. 추가 비용 표본은 훈련 분할252에피소드×3회×(20+40개체)=45,360호출이며 성능으로 조건을 선별하지 않았다.

## 3. 검사와 감사

- 신규20검사: 20/40 초기 집단 공통 부분, 선행 초기화·변이와 난수 일치,32파라미터, scalar/batch 출력·동결, 중단/재개,10/20회차 접두 동일성, 해당 시점 누적 검증 best,0회차 검증 없음, 자료 접근 차단, 캐시·잘못된 잠금 키 거부, 회차/체크포인트 변경 거부, 이진 검정·Holm·10pp·비용 경계를 검사했다.
- 게이트 집계89검사는 신규20+Q1-006의20+Q1-005 이식49다. 별도 과거 이동 검사35개도 통과했으나 게이트의 정규식 집계에는 포함되지 않았다. 이 숫자는 독립 과학 검토나 중복 없는 고유 연구 질문 수가 아니다.
- 예비6작업의3,200개체 평가 기록과76,800에피소드를 모두 환경·보상·종료·선발·계보·재생산 RNG로 감사했다. 미확정 중단 호출0이다. 모든 탐색 신경망 출력을 재실행한 감사는 아니다.
- 기존 Q1-006 소스와 새 소스·고정 의존성49파일을 함께 고정했다. 이후 본 CLI가 비용 미통과를 거부하는지 확인했고 본 출력 디렉터리도 생성되지 않았다.

신규 완주 단위 검사2회의 정책 fixture 호출은6,696회로 공식 준비122,160회와 분리한다. 계승 회귀 검사의 전체 fixture 호출 합계는 미집계이며 공식 성능 실험에 포함하지 않는다. 추가 비용 fixture의45,360호출도 예비76,800과 따로 계수했다. 공식 예비·비용에서 본 검증/테스트 분할 호출은0이다.

## 4. 결과 — 비용 게이트 미통과

| 항목 | 관측 또는 외삽 | 사전 기준 / 상태 |
|---|---:|---|
| 공식 훈련 전용 예비 | 6작업·76,800호출 | 전체 완료·재개·감사 통과 |
| 예비 탐색 / 감사 시간 | 9.259초 / 2.229초 | 이 작은 예비의 측정값 |
| 추가 훈련 분할 비용 표본 | 45,360호출 | 최대48,000 이내 |
| 본 탐색 / 감사 기본 시간 추정 | 약2.219시간 / 0.499시간 | 실제 본 시간 아님 |
| 시간의2배 여유 상한 | **약5.436시간** | 4시간 초과 |
| gzip을 풀어 센 본 JSON 원자료 추정 | **약44.772GiB** | 20GiB 초과 |
| 당시 사용 가능한 디스크 공간 | 약36.095GiB | 예상 비압축 원자료2배+5GiB ≈94.544GiB 미충족 |
| 관측된 작업 프로세스 최대 작업 집합 | 약38.49MiB | 프로세스 수명 최대값; 동시 전체 메모리 최대 아님 |
| 본 / 확인 정책 호출 | **0 / 0** | 실행하지 않음 |

훈련 비용은 예비 단가, 검증 비용은 두 집단 크기 비용 표본 중 큰 단가를 사용했다. 계획 본 훈련38,400,000·검증120,960,000호출에 단가를 곱하고 탐색·감사 시간 합에 여유계수2를 적용했다. 예비가2작업자 병렬이고 검증 비용 표본은 순차 측정이라 보수적이며 엄밀한 소요 시간 보증은 아니다. 파일/중간 이력 규모와 실제 후보의 종료 길이도 본에서 달라질 수 있다.

**44.772GiB는 gzip 해제 후 JSON 부피 추정이다. ZIP 배포 크기 또는 실제 디스크 점유와 같지 않다.** 디스크 기준도 이 비압축 추정에 적용한 계획상 보수적 규칙이다. 현재 PC에서 압축 저장 실행 자체가 불가능하다고 입증한 결과는 아니다. 예비 저장 파일은 약3.94MB였고, 비용 표본 두 파일은 합416,124바이트였다. 저장 표현과 비용 추정 방식을 다음 버전에서 개선할 여지가 있다.

완료율·발견 비율·PT−B/P−T의 본 효과는 **미측정**이다. 준비 표본의 성능을 본 결과로 대체하지 않는다.

## 5. 오류·중단·변경과 보존

첫 개발 검사에서 Windows 샌드박스의 기본 임시 디렉터리 쓰기 권한 오류가 발생했다. 그때 정책 호출0회였다. 작업 공간 안에 임시 폴더를 만들고 정리 전 해석된 경로를 검증하도록 고쳤다. 이는 소스 동결 전 개발 수정이며 본 성능 실패가 아니다. 이후 신규18검사와 최종20검사를 완료했다.

소스 동결 후 예비·감사·비용 표본에 기술 실패는 없었다. 비용 세 기준 모두 미충족이어서 계획대로 본을 보류했다. 거부 동작 확인 명령은 평가 전에 종료됐고 후보나 테스트를 생성하지 않았다. 소스·계획·예비·비용 판정을 수정해 사후 통과로 바꾸지 않는다.

배포 diff 점검에서 계승한 `audit.py`와 `search.py`의 파일 끝 빈 줄2곳이 형식 경고로 남았다. 실행 후 소스 보존 원칙에 따라 공백만을 이유로 동결 파일을 변경하지 않았다. 기능 검사·보관 해시 불일치가 아니라는 범위를 구분한다.

소스 지문: `64b2e8bd4f8cb91539d87f23bb8a3c99af4b3ba779b5fe0057891951fed69944`.
계획 지문: `2108ba0c40782b9def0def07233791e13cbd40e06827de355ac7706ed7e8cca8`.
예비 프로토콜: `e1f32086108d99ad6ecb519485552e510450f1c913ba17be6f5c0bf4bfe39fe2`.

## 6. 해석과 다음 작업

이번에는 **본 성능 측정 전의 자원 게이트**가 작동해 예산을 무제한 확대하지 않았다. 과학적 비교 조건과 성능 결과를 바꾸지 않은 채, 실행 가능한 새 준비 버전이 필요하다는 결론이다.

다음 우선 작업은 **후보·에피소드의 반복 필드를 손실 없이 줄이는 저장 방식과 동일 수치 동작을 보장하는 평가 묶음 처리의 설계**다. 원자료의 복원 일치·행동 동률·난수 대응·후보 순위를 검증하고 새 버전/출력 폴더에서 훈련 전용 비용 검증을 반복한다.80개 시드나 성공 문턱을 낮춰 비용 실패를 숨기는 변경은 하지 않는다.4시간/20GiB 규칙 자체를 고칠 경우에도 물리 저장량과 비압축 논리량을 구분한 근거를 새 사전 계획에 적는다.

[v0.2 기술 준비 계획](../protocols/Q1-007_v02_저장과평가_준비계획.md)에 저장 codec의 완전 복원·기존 평가와 행동 동치·후보 묶음 처리·새 비용 정의의 검증 순서를 작성했다. 아직 구현·실행하지 않았다. F0/F1 채택, 구조 크기 변경, 추가 생애 학습 또는 새 환경 실험으로 넘어간 결과도 아니다.

## 7. 재현과 자료

후속 기술 측정 [Q1-010](Q1-010_기록저장효율_비교.md)에서 기존 예비/비용 자료의 손실 없는 변환·복원과 저장 효율을 비교했다. 이는 당시 준비 결과와 별도 기록이며 v0.1 비용 미통과 판정은 유지한다. v0.2 실행기 통합과 본 실험은 아직 수행하지 않았다.

[실행 게이트](../management/q1_007_execution_gate.json), [검사 로그](../management/q1_007_execution_gate.log), [새 실행기 안내](../../studies/interaction/evosim_q1007_v01/README.md)에 구현·명령·환경이 있다. Python3.12.14·NumPy2.3.5·Windows·작업자2개에서 수행했다. 작업 디렉터리는 `studies/interaction/`이다. 공식 예비를 다시 돌려 덮어쓰지 않는다.

원자료·완료 소스49파일·당시 계획·게이트를326파일 ZIP으로 보관했다. [목록](../../evidence/q1_007_v01.json)의 SHA-256·파일별 해시·ZIP CRC와 기존 로컬 내용 대조를 모두 통과했다. `tools/restore_q1007.py`는 기본으로 검사만 하며 `--restore-missing`에서도 다른 기존 파일을 덮어쓰지 않는다. 자동 보관·감사는 독립 검토가 아니다.

[원자료 Release](https://github.com/paylace/gene-project/releases/tag/q1-007-v01-pilot-2026-10-17)에 게시한3,496,766바이트 ZIP의 GitHub 첨부 해시도 로컬과 일치했다. 구현·준비 결과 커밋19350cb의 [Linux CI](https://github.com/paylace/gene-project/actions/runs/39010342696)도 통과했다. 게시·CI·후속 계획 기록은 완료 원자료 ZIP 바깥의 Git 기록이다.
