## 1. 목적과 범위

같은 정보를 반복 저장하는 비용을 줄이고, 기존 필드를 하나도 잃지 않고 복원할 수 있는지 확인했다. 기존 예비 6작업의 120회차·76,800에피소드 기록과, 훈련 분할로 만든 검증 크기 비용 표본 2파일·45,360기록을 모두 사용했다. 합계 122파일·122,160기록이며 성공 여부로 골라 쓰지 않았다.

새 정책·진화·학습·본 검증/테스트 호출은 **0회**다. 재구성 과정의 환경 행동 재생과 고정 행동 자체 검사는 정책 실행이 아니다. 시드의 성능 차이·발견률을 측정하거나 추가 선발하지 않았다.

## 2. 방법과 완전성

기존 JSON/gzip 수준3과, 같은 JSON/gzip 수준9를 대조했다. 이후 공통 에피소드·반복 순서와 유전체를 파일 안에서 공유하고 레코드를 열 목록으로 바꾸는 조건, 행동으로 보상·결과를 복원하는 조건, 동일 행동열을 사전으로 묶는 조건, 고유 행동열을2비트·base64로 담는 조건을 단계적으로 비교했다. 구조 변경 조건의 gzip 수준은 모두3이다. 조건 사이 변화는 순차적이며 각 기법의 독립적 요인 효과 실험은 아니다.

유전체·계보·순위·실제 선발 지표·동률 횟수 등은 보존했다. 복원에는 축소 파일과 동결 환경 코드를 사용했고 원본 JSON에서 누락값을 가져오지 않았다. 변환 전에 원본 전체 canonical JSON의 해시를 저장하고, 복원 후 원본 gzip 해제 **전체 바이트와 동일한지** 확인했다. 필드별 값·숫자/불리언 형식·배열 순서를 모두 포함한다. 축소 내용 자체의 해시도 별도로 확인한다. 해시는 손상 검출용이며 원자료 작성자의 진실성이나 악의적인 전면 재작성을 인증하는 서명은 아니다.

모든 조건을 새 자식 프로세스에서3회, 미리 섞은 순서로 측정했다. 매회 파일을 실제로 쓰고 읽었다. 파일 안에서 동일한 초기 조건·행동·훈련 여부의 복원 결과는 메모리에 재사용했다. 파일 단위로 처리했으며 전체 자료를 한 번에 펼치지 않았다. 시간은3회 중앙값이며 운영체제 캐시는 통제하지 않았다. 변환 시간에는 JSON 직렬화·해시·압축·쓰기를, 복원 시간에는 읽기·압축 해제·재구성·해시·원본 바이트 비교를 포함한다. 원본 읽기는 별도 계수했다.

## 3. 저장 크기 결과

아래 MB는1,000,000바이트다. 실제 저장 크기는 파일 내용 바이트 합계이며 파일시스템 할당 블록, 배포 ZIP, 측정 도구 자체의 자료는 포함하지 않는다.

| 저장 방식 | 압축 파일 MB | 기존 대비 축소 | 압축 해제 MB | 해제 부피 축소 |
|---|---:|---:|---:|---:|
| 기존 JSON·gzip3 | 3.138515 | 0% | 43.373120 | 0% |
| 기존 JSON·gzip9 | 1.997967 | 36.34% | 43.373120 | 0% |
| 공통 정보 공유·열 목록 | 1.994942 | 36.44% | 24.387757 | 43.77% |
| 행동으로 결과 복원 | 1.259717 | 59.86% | 8.990371 | 79.27% |
| 동일 행동열 사전 추가 | 1.211416 | 61.40% | 6.496018 | 85.02% |
| 행동열2비트 추가 | 1.208615 | 61.49% | 6.311992 | 85.45% |

모든 방식·3회에서 파일 크기가 일정했고 복원 바이트가 전부 일치했다. 총 18조건 실행×122파일=2,196파일 비교·2,198,880에피소드 레코드 상당의 비교다. 독립 정책 실험 수가 증가한 것이 아니다. 입력 전체272파일의 작업 전후 SHA-256도 모두 같았다.

### 전체 폴더와 자료 종류의 차이

변경하지 않은 프로토콜·체크포인트·실패/재개 원장 등150파일은1,216,905바이트다. 이를 포함하면 원래 폴더는4,355,420바이트이고,2비트 방식의 회차/표본 파일로 대체했을 때2,425,520바이트로 **44.31%** 줄어든다. 행동열 사전 방식은2,428,321바이트·44.25%, gzip9만 적용하면3,214,872바이트·26.19% 축소다. 실제 원본은 대체·삭제하지 않았다.

같은2비트 방식도 훈련 회차의 압축 크기는56.87%, 검증 크기 비용 표본은91.71% 줄었다. 표본은252개 훈련 에피소드×3반복이고 회차는24개이므로 반복성과 메타데이터 비중이 다르다. 이 차이 때문에 합산 축소율을 본 전체에 그대로 적용할 수 없다. 이전 비용 기록의 비압축44.77GiB와 이번 압축 파일 크기를 직접 비교해서도 안 된다.

## 4. 시간·메모리와 절충

| 방식 | 변환·저장 중앙값 초 | 복원·검증 중앙값 초 | 최대 메모리 MiB |
|---|---:|---:|---:|
| 기존 JSON·gzip3 | 1.015 | 1.093 | 111.02 |
| 기존 JSON·gzip9 | 1.632 | 1.121 | 111.12 |
| 공통 정보 공유·열 목록 | 1.981 | 3.317 | 121.99 |
| 행동으로 결과 복원 | 1.362 | 5.253 | 109.94 |
| 동일 행동열 사전 추가 | 1.663 | 5.297 | 105.86 |
| 행동열2비트 추가 | 1.572 | 5.358 | 107.09 |

메모리는 각 자식 프로세스 수명 동안의 최대 working set 중 최댓값이다. 검사를 위해 원본과 복원본을 함께 보유하므로 실제 운영 복원기의 최소 필요 메모리로 해석하지 않는다. 세 번의 실행만으로 속도의 통계적 차이나 일반적인 성능 우위를 주장하지 않는다.

동일 행동열 사전은 기본 방식보다 읽기·복원 검증이 약4.85배 걸렸다. 따라서 용량 감소를 전체 실행 시간 개선으로 부를 수 없다.2비트화의 추가 절감은 행동열 사전 대비 **2,801바이트·약0.23%**에 불과했다. 훈련 회차에서는2,836바이트 줄었지만 비용 표본에서는35바이트 늘었다. 기본 gzip이 이미 반복 행동 문자열을 잘 압축하며, 비트 표현에도 길이·base64 비용이 든다.

## 5. 오류·중단·이상값

동일 행동열 사전의 두 번째 실행에서 복원 누적 시간이 **15,055.986초**로 기록됐다. 다른 두 실행은5.297초·5.238초다. 시스템 대기·절전 등의 영향 가능성은 있으나 원인은 확인되지 않았다. 이상값을 삭제하거나 재측정으로 덮어쓰지 않았다. 사전에 정한3회 중앙값을 그대로 사용하고 전체 실행값을 요약 JSON에 보존했다. 이 값으로 본 실행 시간 상한을 산출하지 않는다.

도구 사전 검사14항목은 네 축소 방식의 왕복·내용 손상 거부·내용 해시를 다시 계산해도 원본 기록 변경을 거부하는지,72개 길이/패턴의 비트 왕복, 잘못된 행동/패딩/길이 거부를 확인했다. 이14항목은14개의 독립 연구 검토가 아니다. 본 측정에서 복원 불일치·원본 변경·정책 호출은 없었다.

원본 보존에 더해18개 비교 사본을 모두 남겨 약32.43MB의 압축 사본 공간을 사용했다. 이는 벤치마크를 보존하기 위한 추가량이다. 이번 작업이 기존 연구 폴더를 실제로 축소했다는 뜻은 아니다.

## 6. 판단과 다음 단계

이번 자료에서는 **행동으로 결과를 복원하고 동일 행동열을 묶는 방식**이61.40%의 압축 파일 축소를 얻었다.2비트화의 추가 효과는 작으므로 다음 운영 형식의 우선 요소로 삼을 필요가 적다. 가장 단순한 절충은 JSON을 유지하고 gzip 수준만9로 높이는 것으로, 압축 파일36.34% 감소와 비슷한 읽기 시간이었다. 다만 논리 레코드 부피는 줄지 않는다.

다음 판단은 사용 목적에 따라 나눈다. 자주 읽는 실행 자료는 단순 형식이나 필요한 지표를 즉시 읽는 구조가 유리할 수 있다. 장기 보관은 손실 없는 행동열 사전 형식이 후보가 된다. 원본 해시·실제 지표와 복원 가능한 행동 증거를 함께 유지해야 한다.

이 도구는 저장 비교용이며 Q1-007 v0.2 실행기에 아직 통합하지 않았다. 본 채택 전에는 새 버전에서 감사·중단/재개·후보 잠금·부적합 입력 거부·훈련 전용 비용을 다시 확인해야 한다. 본 시간4시간/저장20GiB 게이트의 통과는 미확인이다. 본·확인 호출0과 v0.1 비용 미통과 판정은 유지한다.

## 7. 재현과 자료 보존

측정 도구: [measure_q1007_storage.py](../../tools/measure_q1007_storage.py). 도구 SHA-256: `58caa9ecf97d1e124380ec058ed1d0986721d1cedac61eed3e48324976074546`.

[산출물 재점검](../management/q1_010_artifact_check.json)에서 입력272파일·동결 의존 코드2파일·변환 사본2,196파일의 크기/해시와 도구·계획 해시 일치를 다시 확인했다. 자동 점검이며 독립 검토는 아니다.

기계 계획 SHA-256: `b63fad57e29962e923f19d8497177fd6f4e15f9bde921818c96c6b6c6015f965`. 입력 경로·272개 해시·동결 의존 코드 해시·조건 순서·환경 버전·자체 검사 결과는 계획 JSON에 있다.3회×6조건의 개별 측정 JSON에는 파일별 변환 크기·사본 해시가 있다. 이 메타데이터는 Git에 보존하며 큰 변환 사본은 로컬 별도 폴더에 보존한다. 입력은 [Q1-007 원자료 Release](https://github.com/paylace/gene-project/releases/tag/q1-007-v01-pilot-2026-10-17)에서 복원할 수 있다.

작업 디렉터리는 `studies/interaction/`이다. 새 재현 디렉터리로 다음 명령을 실행한다. 기존 출력 폴더는 덮어쓰지 않는다.

```powershell
python -B -X utf8 ../../tools/measure_q1007_storage.py --selftest
python -B -u -X utf8 ../../tools/measure_q1007_storage.py --output storage_q1007_reproduction_v01
```

원본 복원 검사를 통과한 사실은 원래 네트워크가 실제로 그 행동을 출력했는지에 대한 별도 재평가나 환경 자체의 독립적 과학 검토가 아니다. 원래 관측 기록과 변환 기록의 동일성을 확인한 것이다.
