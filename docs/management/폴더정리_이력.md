# 폴더·문서 정리 이력

정리일: 2026-10-15. 수행: Codex. 요청: 사용자 — 연구별 배치와 읽기 쉬운 보고서 분리, 보고서 양식·규칙 파일, 실험 보고서 말미의 수행자 명시.

## 수행 내용

1. 정리 전 13개 이동 단위와 2,924개 원본 파일의 경로·크기·SHA-256을 기록했다.
2. 모든 이동 원본과 목적지의 절대 경로가 작업 폴더 안에 있는지 검사했다. 기존 목적지는 덮어쓰지 않았다.
3. 연구 코드·원자료는 연구별 묶음, 초기 코드·검토·참고자료는 보존 폴더로 이동했다.
4. 목적·계획·현황·설계·일지·공식 보고서 8개를 분리하고 규칙·양식·안내를 작성했다.
5. 이전의 긴 통합 문서는 원본 그대로 보존했다. 루트의 같은 파일명은 새 안내로 만들었다.
6. 원래 코드·프로토콜·결과·README·로그의 내용을 바꾸지 않았다. 기존 README의 상대 문서 링크는 작은 안내 파일을 추가해 유지했다.

## 검증과 범위

이동 직후 원본 2,924개 모두 내용이 일치했다. 검사 결과는 [원본 보존 검사](preservation_check.json), 전체 대응은 [이동 명세](relocation_manifest.json)에서 확인한다. 재배치 후에는 활성 문서 링크·보고서 말미 수행 기록·기록된 코드 해시·두 실행 묶음의 테스트를 검사한다. 최종 점검 결과는 이 폴더의 `layout_check.json`, `verification.json`, `verification_console.log`로 남긴다.

실험을 새로 수행하거나 기존 결론을 바꾸는 작업은 하지 않는다. 과거 통합 문서의 세부 설계 절은 출처와 작성 당시 상태를 밝힌 분리 기록이다. 공식 보고서는 원자료와 원래 집계를 바탕으로 새로 읽기 쉽게 구성한 문서이며 독립 검토 완료로 표시하지 않는다.

## 최종 확인

- 이동 전 원본 2,924개는 테스트 후에도 모두 원래 SHA-256과 일치했다.
- 공식 보고서 8개 모두 마지막 절의 수행자·작성자·모델 기록·독립 검토 상태 검사를 통과했다.
- 활성 문서의 로컬 링크가 모두 존재하고 완료 실행에 기록된 코드 30개 파일의 해시가 일치했다.
- 새 작업 위치에서 작업 기억 테스트 14개, 상호작용 테스트 21개가 모두 통과했다. 본 실험은 다시 실행하지 않았다.
- 재개 테스트의 임시 파일은 원래 코드를 수정하지 않고 검사 실행기에서 작업 폴더 안에 생성하도록 지정했다.
- 향후 에이전트도 작성 규칙과 수행자 기록을 따르도록 루트 `AGENTS.md`에 지침을 연결했다.
- 정리 도구는 사람이 편집한 문서를 다시 생성해 덮어쓰지 않도록 보호한다. 이동도 기존 목적지를 덮어쓰지 않는다.
