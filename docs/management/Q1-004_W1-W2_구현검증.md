# Q1-004 W1/W2 구현·정합성 검사 기록

버전 1.0 / 2026-10-16 한국 시간 / 구현 검증 완료·독립 검토 미실시. Q1-004의 중간 구현 기록이며 본 실험 결과 보고서가 아니다.

## 목적과 범위

[계획](../protocols/Q1-004_v02_실험계획.md)의 세 조건을 실제 생성·변이·교차·저장/복원에 집행하면서 A0의 기존 동작을 보존하는지 확인했다. [별도 패키지](../../studies/interaction/evosim_interaction_v02/)에 W1/W2를 구현했다. 완료된 v0.1 소스·프로토콜·원자료는 수정하지 않았다.

- W1: 불변 Settings, 원래 제안 모수와 실제 구조 제약 분리, 엄격한 유전자 디코딩과 조건/해시를 담은 저장본.
- W2: 공통 원형 기반 초기화, 6종 변이, 우성 부모 교차, 단조 증가 모듈 ID, 한 회차 번식·계보·거부 제안 기록.
- W3 준비: 기존 수치 계산 순서의 scalar/batch 정책만 분리했다. 전체 평가기와 관찰기는 미구현이다.
- W4 이후: 탐색 실행기·후보 잠금·checkpoint 재개·전체 분석·감사는 미구현이다. 유전체 저장본 복원을 실행 중단/재개 구현 완료로 표현하지 않는다.

## 방법과 통과 결과

[자동 검사 JSON](q1_004_core_checks.json)에 실행 명령·Python 버전·소스 SHA-256·검사 전후 불변 여부를 기록했다. 전체 콘솔 로그는 같은 이름의 로컬 .log 파일로 보존했다.

| 검사 | 사례 | 관측 결과 |
|---|---|---|
| A0 초기화 | 시드201,205,210 × 20개 | v0.1 유전체 직렬화·해시·생성 후 RNG 상태 일치 |
| 공통 원형 | 같은 3시드·20개 × A0/A1/A2 | 공통 ff·원형 모수·초기 RNG 일치, 조건별 변환만 다름 |
| 강제 변이 | 위 A0 60개 × 6종 = 360사례 | 최종 유전체·RNG·ID·기존 이벤트 필드 일치 |
| 변이 경계·교차 | 추가/제거 제한과 자연 추첨, 점수·슬롯 동점 | 기존 결과와 RNG 일치, 우성 부모의 고유 모듈 보존 |
| 번식 | 3시드 × 합성 점수5회차 × 20개 | 자손·부모 슬롯·기존 계보 필드·RNG·ID 일치. 과제 성능 탐색 아님 |
| A1 제약 | 출력 자기순환/교차 출력 rec/모듈 rec/ema/latch 강제 제안 | 출력 자기순환만 거부, 나머지 기억 경로 허용 |
| A2 제약 | rec 생성, rec 삭제 선택, 기억 op, 새 모듈 | 무효 제안 재추첨 없음, 정해진 weight까지 추첨, rec=={}·허용 op 유지 |
| 부분 거부 | 금지 op와 허용 bias 변경을 함께 제안 | proposal_rejected와 changed를 각각 기록 |
| 저장·교차 | 각 조건120회 연산·교차·JSON 왕복 | 조건 유지, 부모 불변, 조건/해시 불일치 거부 |
| 오류 입력 | 빈 rec 사전, 금지 op, NaN/Inf/bool, 잘못된 ID·간선·DAG·설정·ID 할당기 | 수리·성능0 대체 없이 거부 |
| scalar 계산 | A0 60개 × 관측10개 | 기존 scalar의 활성·행동·RNG 정확 일치 |
| batch 계산 | 6연산 × 24스텝 × 3열 | 기존 batch와 정확 일치, scalar 대비 rtol=atol=1e-12 통과 |
| 에피소드 동작 | 개체3개+완전 동률 사례, train 앞18개 × 2반복 | 새/기존 scalar의 행동·보상·종료 기록 일치, 상태 초기화·유전체 동결 확인 |

새 기반 코드 **25테스트**, 기존 WM/Q1 **35테스트**, 계획 도구 **12테스트**가 모두 통과했다. 문서 점검에서 동결 소스 30개의 해시가 일치했다. 신규 검사 도구는 v0.1 기준 소스15개와 새 코드/테스트 해시도 별도로 검사한다. CI에 신규 검사를 추가했다.

위 횟수는 개별 검사의 사례 수이며 독립 연구 시드 수나 본 실험 평가 예산으로 집계하지 않는다. 테스트 점수로 비교 조건·임계값을 고르지 않았다. benchmark test의 성능 평가는 열지 않았다.

## 오류·변경과 해석 한계

첫 23개 검사는 통과했다. 정적 검토에서 저장본의 True/1 형식 혼동과 오래된 ID 할당기를 더 일찍 거부할 필요를 확인해 검증을 보강하고, A1 기억 연산 허용/ID 검사를 추가하여 최종25개가 통과했다. 성능 실험 실패를 숨기거나 성공 사례만 선별한 변경이 아니다. 개발 중 테스트 대역은 RNG 소비 순서를 검사하기 위한 것이며 실제 RNG를 대체하지 않는다.

관측한 사례에서 A0 정합성과 조건 집행이 확인되었다. 전체 실행기·관찰기·재개·모든 저장 개체 감사는 아직 없으므로 **W6 전체 통과나 모든 버그의 부재를 뜻하지 않는다.** A1/A2 성능 개선은 아직 측정하지 않았다. 이 단계에서는 예비901/902, 본 비교201~210, 확인301~310의 성능 탐색을 실행하지 않았다.

## 재현과 다음 단계

저장소 루트에서 다음 명령을 사용한다.

```powershell
python -B -X utf8 tools/check_q1_core.py
python -B -X utf8 -m unittest discover -s tools/tests -v
python -B -X utf8 tools/check_research_layout.py --tests
```

신규 검사 도구의 기본 출력은 `dist/q1_core_verification/`이다. 보존용 검사 기록은 `--output docs/management/q1_004_core_checks.json`으로 생성했다. 기존 테스트의 임시 산출물은 원래 검사 도구 규칙대로 별도 보존한다.

다음은 W3의 독립 상태를 갖는 동결 평가기와 상태/RNG를 바꾸지 않는 관찰기다. 이후 W4 후보 선발·잠금·원자 저장·재개를 구현한다. 그 뒤 W5/W6를 통과해야 예비 비용 측정으로 넘어간다. 초안 JSON의 locked=false 및 전체 구현 소스 해시 미지정 상태는 유지한다.
