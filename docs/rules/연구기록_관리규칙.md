## 실험 자료

실험 ID와 기계 실행 버전은 구분한다. 같은 본 실험의 사후 진단에는 별도 보고서 ID를 부여하고 원래 후보·데이터 의존성을 적는다. 원자료가 같은 연구 결과 폴더에 있어도 보고서는 목적에 따라 나눌 수 있다.

실행 전에는 조건·선발·판정·난수·데이터·코드 해시를 저장한다. 실행 중에는 성공·실패·체크포인트·명령 출력을 보존한다. 완료 뒤에는 원자료에서 지표를 다시 계산하고 그 결과를 보고서로 연결한다.

## 동결 자료와 변경

- 완료된 실행의 코드 해시·프로토콜·원자료는 소급 수정하지 않는다.
- 알고리즘이나 실험 조건이 바뀌면 새 버전·새 출력 폴더를 사용한다.
- 문서 편집은 정리·표현 변경과 내용 변경을 구분한다. 내용 변경은 변경 근거와 영향 범위를 일지에 기록한다.
- 당시 문서에 남은 예정 표현은 역사 상태다. 현재 현황을 여러 곳에서 서로 다르게 관리하지 않는다.
- 새로운 실험의 공식 결과는 먼저 보고서에 적고 현황에는 짧은 요약과 링크를 남긴다.

## 파일 이동

이동 전에 원래 경로·새 경로·크기·SHA-256 목록을 만든다. 실제 원본 파일 이동은 이 목록에 따라 수행하고 이동 후 내용을 비교한다. 삭제나 덮어쓰기 없이 옮기며, 내용을 바꿔야 하면 원본을 별도 보존한다.

연구별 실행 경로에 의존하는 파일은 한 묶음으로 옮긴다. 이번에는 Q1 패키지 내부의 코드·데이터 상대 배치를 유지해 소스 해시와 재개 명령을 보존했다. 불필요해 보이는 과거 로그·캐시·외부 대화 자료도 임의 삭제하지 않았다.

## 완료 시 갱신

보고서·현황·일지·목록을 갱신하고 [보고서 작성 규칙](보고서_작성규칙.md)의 마지막 수행 기록을 점검한다. 자동 링크 검사와 재현 경로 검사는 내용의 과학적 타당성이나 인간 독립 검토를 대신하지 않는다.
