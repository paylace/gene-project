| 항목 | 구현 계약 |

모듈 ID는 실행별 4에서 시작해 증가만 하며 다음 ID를 checkpoint에 보존한다. 교차는 훈련 점수, 동점이면 낮은 슬롯을 우성으로 정한다. 다른 조건의 부모를 섞지 않는다. 독립 실행 사이에서 같은 ID 숫자를 쓰는 것은 오류가 아니다.

## 2. 변이·난수 소비 계약

원래 `random.choices` 가중치 합은 **1.10**이다. 아래 확률은 비엘리트 자손의 변이 적용 추첨(0.50)을 통과한 뒤의 조건부 확률이다. 전체 자손 비율이나 실현된 변경률과 다르다.

| 제안 | 가중치 | 조건부 확률 | 제약 처리 |
|---|---:|---:|---|
| weight | 0.42 | 38.1818% | A2 금지 op 제안만 거부. bias/decay·허용 간선 변경은 계속 |
| add_module | 0.12 | 10.9091% | 원형을 생성한 뒤 A2의 ema/latch→tanh, rec 삭제 |
| remove_module | 0.06 | 5.4545% | 기존 모듈 수 제한·출력 연결 보완 유지 |
| add_ff | 0.18 | 16.3636% | 기존 중복·DAG 검사 유지 |
| add_rec | 0.22 | 20.0000% | A1 출력 자기순환, A2 모든 제안 무효 |
| remove_edge | 0.10 | 9.0909% | 원래 rec/ff 선택 유지. 삭제 대상 없으면 무효 |

금지 제안은 재추첨하지 않는다. 다음 소비 순서를 고정한다.

1. `add_rec`: 기존 정렬 목록에서 target, source를 뽑는다. 해당 간선이 없을 때만 기존대로 weight도 뽑고, 조건 위반이면 버린다. 중복이면 weight를 뽑지 않는다. A2는 항상 빈 rec이므로 weight까지 소비한다.
2. `add_module`: 기존 수 제한 확인→ID 할당→op/bias/decay→입력 source/weight→자기순환 여부와 해당 시 weight→출력 target/weight 순서를 유지한다. 그 후 A2 변환을 적용한다. 모듈 생성 전체를 무효로 하지 않는다.
3. `weight`: op 변경 여부와 기존 6종 제안 추첨을 유지한다. 금지 op면 현재 op를 보존하고 뒤의 bias/decay 추첨을 계속한다. 간선 변경은 실제 존재하는 간선에서 기존 순서대로 시행한다.
4. `remove_edge`: rec 선택 확률 0.4를 유지한다. 선택 사전에서 간선 수가 2개 이상인 target만 삭제 대상으로 삼는 v0.1 규칙을 유지한다. 대상이 없으면 target/source 추첨 없이 끝낸다. rec 실패를 ff로 전환하지 않는다.
5. A0는 모든 분기와 RNG 상태가 v0.1과 같아야 한다. A1/A2는 실제 구조 때문에 후속 분기가 달라질 수 있다. 전체 탐색 난수 궤적의 조건 간 일치를 주장하지 않는다.

`proposal_rejected`는 제약으로 제안 일부가 거부됐는지, `changed`는 최종 유전체 해시가 바뀌었는지다. 금지 op를 거부해도 bias는 바뀔 수 있으므로 둘 다 참일 수 있다. 원인은 `condition_forbidden`, `duplicate_edge`, `ff_cycle`, `module_limit`, `no_removable_target`, `no_parameter_change`로 구분하고 복수 원인은 목록으로 남긴다. 변이 자체를 적용하지 않은 자손은 무효 변이율 분모에서 제외한다.

## 3. 평가·분석 계약

`derive_seed`는 인자 배열을 `json.dumps(parts, ensure_ascii=True, separators=(",", ":"))`로 ASCII 인코딩하고 SHA-256 전체를 big-endian 정수로 바꾼다. Python `random.Random`을 목적별로 분리한다.

| 용도 | 파생 인자 |
|---|---|
| 초기/탐색 | `("initial", seed)` / `("search", seed, method)` |
| 훈련 목록 | `("training_batch", seed, generation)`; train 목록 순서를 유지한 비복원 24개 |
| 행동 동률 | `(purpose, seed, episode_id, repeat)` |
| purpose | `train:{generation}`, `validation`, `test` |
| 프로브 | `("probe", seed, repeat, position, left, right)` |

평가 난수에 condition·후보 역할을 추가하지 않는다. 탐색 RNG를 로깅·평가·비용 추정에 쓰지 않는다. 행동 선택은 기존 로짓→최댓값 차이 [-10,10] 제한→softmax→동률 처리 순서를 유지한다. `linear` 모듈도 기존 sigmoid 동작을 보존한다.

평가 캐시는 `(protocol_digest, settings_digest, genome_digest, dataset_digest, run_seed, purpose, repeats, state_mode)`가 모두 같을 때만 사용하며 재사용 출처를 남긴다. 관찰 로그는 관찰기 버전까지 포함한다. 논리 평가 슬롯과 실제 호출 수를 따로 기록한다.

시드별 S를 먼저 평균한다. 차이의 표준편차는 `ddof=1`이다. 짝 부트스트랩은 NumPy `default_rng(72004).integers(0,10,size=(10000,10))` 인덱스를 한 번 생성해 모든 대비에 공통 적용한다. `percentile(...,[2.5,97.5],method="linear")`를 쓰고 NumPy 버전을 기록한다. 정확 부호 검정은 `sum(comb(10,j) for j in range(K,11))/2**10`이다. Holm은 p 오름차순으로 0.025→0.05, 앞 단계 실패 시 뒤도 기각하지 않는다. 동률 p의 출력 순서는 A1,A2다.

0.10은 **10%포인트**다. 주 판정은 평균 차이·양수 시드·Holm 세 요건이다. 8개 양수는 부호 검정에 부족하여 실제 최소 9개 양수가 필요하다. 확인 단계도 n=10, 단일 대비 α=0.05여서 실제 최소 9개 양수다. 보조 6개 대비는 탐색적으로 표시한다.

## 4. 파일·상태·재개 계약

신규 패키지의 기반 기능만 구현했다. 아래 출력·전체 실행 형식은 **구현할 대상**이며 아직 동작하는 탐색 명령이 아니다.

| 산출물 | 예정 경로·필수 내용 |
|---|---|
| 신규 패키지 | `studies/interaction/evosim_interaction_v02/`; 설정·유전 연산·평가·탐색·분석·감사·실행기 |
| 출력 루트 | `studies/interaction/results_v02/{pilot,main,confirmation}/` |

| 진단·집계 | `test.json.gz`, `probe.json.gz`, `diagnostics.json.gz`, `analysis.json`, `audit.json` |

SELECTED는 확인 구조가 정해진 뒤 A1 또는 A2로 해소한다. 설정은 불변 객체로 모든 생성·변이·교차·정책·역직렬화에 전달한다. A0 공통값은 동결 [v0.1 프로토콜](../../studies/interaction/evosim_interaction/results_v01/protocol.json)의 settings와 동일하고 A1/A2의 제약은 별도 필드다. 초기 원형 변환 외에는 위반 개체를 수리하지 않고 오류로 중단한다.

새 프로토콜은 `ensure_ascii=True, sort_keys=True, separators=(",", ":"), allow_nan=False` JSON의 SHA-256으로 식별한다. 자기 해시 필드는 해시 대상에서 제외한다. 소스 매니페스트에 선발·분석·감사·진단·테스트까지 포함한다. 소스가 바뀌면 기존 재개를 거부한다.

checkpoint 식별자는 `experiment_id, protocol_digest, source_digest, settings_digest, dataset_digest, condition, method, seed, rounds, population, phase`를 포함한다. 다음 회차, 전체 집단·계보, 다음 모듈 ID, 검색 RNG 상태, initial/best, 이력, 실제 평가 횟수·누적 시간을 보존한다. 완료 result를 먼저 쓰고 checkpoint를 원자 교체한다. 기존 회차 파일의 완료 해시를 대조하고 재계산 결과가 다르면 덮어쓰지 않고 실패를 기록한다.

본 비교 후보 잠금은 60실행의 완료 여부, 세 역할별 해시·선발 회차/슬롯·검증 지표·검증 기록 해시, blind 인덱스·패턴·검증 지표를 포함한다. 누락 시 테스트를 열지 않는다. 확인은 별도의 40실행 잠금을 둔다. 예비는 검증·테스트 평가 API를 허용하지 않는다. 정적 목록 생성과 정책 평가를 구분한다.

변이/교차에는 실행 식별자·회차/슬롯·부모 슬롯/해시·우성 부모·신규 ID·제안·거부 원인·before/after 해시를 남긴다. 회차별 훈련 목록과 전 후보 유전체·훈련 기록·해당 시 검증 기록을 보존한다. 비유한 값·누락·조건 위반은 기술 오류이며 성능 0으로 대체하지 않는다.

best 행동 로그에는 이전 전체 상태 해시, 관측 4개, 로짓 3개, 선택/정답 행동, 보상·종료, 로짓 격차를 남긴다. 반사 진단은 이전 전체 상태와 RNG를 복제해 원래/반사 입력을 각각 한 번 계산한다. 실제 경로에는 쓰지 않는다. 적격 방문 수와 양방향 정답/단순 전환의 분자·분모를 보존한다.

W6 최소 인수 사례:

- A0 초기화는 시드201,205,210에서 각20개 직렬화·최종 RNG 상태를 v0.1과 정확히 대조한다. 같은 부모의 6종 강제 변이·교차·한 회차 번식도 대조한다. 로그 추가가 RNG·유전체를 바꾸면 실패다.
- A0 평가의 행동·보상·종료·동률 선택을 기존의 같은 backend와 정확히 대조한다. scalar↔batch 활성은 `rtol=atol=1e-12`, 행동·보상은 정확 일치를 요구한다. 동률 경계의 기존 불일치도 기록하고 실행 전에 해결한다.
- 출력 자기순환/출력 간 교차 rec/모듈 자기 rec/ema/latch를 강제 제안한다. A1은 출력 자기순환만 거부하고 A2는 모두 거부해야 한다. 각 연산·저장·복원 후 검사하고 다른 설정의 부모/체크포인트는 거부한다.
- 관찰기 켬/끔의 행동·보상·최종 상태·RNG가 같아야 한다. 반사 진단이 실제 상태/RNG를 바꾸면 실패다. 규칙 정책은 전체1,512조합에서 최단 해결을 확인한다.
- 연속5회차와 2회차 중단+3회차 재개의 집단·계보·RNG·선발·평가 횟수가 같아야 한다. 시간·프로세스 식별자만 비교에서 제외한다. 저장 도중 실패와 result/체크포인트 순서도 검사한다.
- 분석은 0차이,8/10,9/10,p동점,Holm 첫 단계 실패,평균 미달,둘 다 통과/A2만 통과/둘 다 실패,분모0(null)을 포함한다. 테스트 점수를 교란해도 후보 선발은 바뀌지 않아야 한다.

기술 실패는 원자료·오류를 남기고 새 소스/프로토콜로 재시작한다. 낮은 점수를 이유로 시드·회차·지표를 바꾸지 않는다. 새 검토 의견은 반영 여부·이유·버전 차이를 남긴다. 독립 검토가 아직 없다는 사실을 승인으로 해석하지 않는다.

저장소 루트에서 Python3.11 이상으로 다음 명령을 실행할 수 있다. 정책 평가·새 실험을 실행하지 않는다.

python -B -X utf8 -m unittest discover -s tools/tests -v

계획 도구는 초안·15개 v0.1 소스·분할·작업 수를 검사해 JSON을 표준 출력한다. 현재 core 검사 도구는 전체 패키지52개 검사를 실행한다. `tools/check_q1_execution.py`는 기존47개 검사와 합쳐 게이트를 기록한다. 실제 예비·본 실행 명령과 비용은 [실행 준비 기록](../management/Q1-004_실행준비검증.md)에 있다. 자동 검사 통과는 모든 버그의 부재나 독립 검토를 의미하지 않는다.
