# Q1-007 v0.2 준비 계획 — 손실 없는 기록 축소와 평가 묶음 처리

작성일: 2026-10-17 한국 시간. 상태: 기술 준비 설계, 새 소스·예비·본 미실행.

[v0.1 준비 결과](../reports/Q1-007_탐색예산_비교.md)는 기능 검증·예비를 통과했으나 시간의2배 상한5.44시간·gzip 해제 JSON44.77GiB로 비용 기준을 넘었다. v0.1 소스·예비·계획·비용 미통과 판정은 보존한다. 이번 문서는 그 실패를 통과로 고치는 문서가 아니라 **별도 버전의 기술 검증 순서**다.

## 1. 유지할 과학적 조건

[원래 설계](Q1-007_탐색예산_실험계획.md)의 고정4모듈·R0/S0·유전 연산·초기화·80짝 시드·네 끝점·무작위 대조·훈련/검증/테스트 분할·검증 일정·선발·판정은 유지한다. 예비 성능에 따라 조건을 바꾸지 않는다. 본 시드는 아직 쓰지 않았으므로 같은 예약 범위를 그대로 둘 수 있다. 새로운 기술 검증 시드는 본과 별도 범위로 실행 명세에 잠근다.

## 2. 먼저 저장을 손실 없이 줄인다

회차 안의 모든 후보가 공유하는 에피소드 순서·반복 번호·고정 환경 정보를 공통 메타데이터로 저장한다. 개별 행동열과 유전체·필요한 지표를 보존하고, 환경에서 결정적으로 재구성되는 보상·최종 위치·벽 충돌·수집 결과·진행 단위는 복원 가능한 표현으로 줄인다. 정책 출력 동률 수처럼 행동만으로 복원되지 않는 값은 따로 보존한다.

저장 계층은 읽을 때 기존 감사기가 사용하는 전체 레코드 구조를 정확히 복원해야 한다. 단순 gzip 압축률 개선과 논리 레코드 축소를 구분한다. 새로운 형식은 명시적인 schema 버전·에피소드 목록 해시·내용 해시를 갖고, 잘못된 행동·메타데이터·누락·중복·길이·중간 종료를 거부한다.

완료 조건은 다양한 훈련/검증 크기의 fixture에서 **원 레코드→축소 저장→복원한 레코드의 모든 필드가 완전히 동일**하고, 그 기록을 기존 감사기가 통과하는 것이다. 임의 사례 몇 개가 맞는 것으로 손실 없음을 주장하지 않는다. 미래 출력·정책을 생략한 뒤 손실 없는 원자료라고 부르지도 않는다.

## 3. 고정 구조 후보를 함께 평가한다

F0의 동일 그래프에서 후보 축과 에피소드 축을 묶어 NumPy로 평가하는 경로를 별도로 만든다. 노드·입력 가중치 합산 순서와 tanh 범위, 동률 판정·난수 키·추첨 순서를 유지한다. 네트워크 입력에 다른 후보의 상태가 섞이지 않아야 한다.

비교 기준은 v0.1 scalar/개별 후보 batch다. 무작위·경계 가중치·출력 동률·빠른 종료·벽 반복·목표 전환을 포함한 fixture에서 출력·행동·보상·선발 순위·유전체 동결을 대조한다. 수치 허용 오차만 맞고 행동이 달라지면 동치 경로로 채택하지 않는다. 필요하면 수치 경계에서는 기존 평가 경로를 사용하며 실제 fallback 비용도 계수한다.

## 4. 새 비용 게이트와 저장량의 뜻

시간4시간·저장20GiB의 수치 문턱을 임의로 높이지 않는다. v0.1은 gzip 해제 후 확장 레코드 JSON을 세었다. v0.2가 손실 없는 별도 형식을 사용하면 **새 형식의 gzip 해제 바이트, 실제 저장 바이트, 전체 레코드로 복원했을 때의 논리 부피**를 모두 보고한다. 저장 기준에 어떤 양을 적용할지는 새 사전 수치 명세에 분명히 적고 원래 기준에서의 변경이라고 밝힌다. 이름만 바꿔 같은 자료를 통과시키지 않는다.

복원·감사가 전체 확장 자료를 디스크/메모리에 동시에 펼치지 않고 회차 단위로 동작하는지 확인한다. 디스크 여유 규칙은 실제 필요한 원본·복원 임시 공간·배포 보관본을 각각 더해 산정하고, 기존의 비압축 추정2배+5GiB 규칙과 수치를 나란히 보인다. 실제 기준 개정의 근거와 보수 계수를 본 전 문서에 잠근다.

## 5. 실행 순서와 중단

1. 별도 `evosim_q1007_v02/`와 `results_q1007_v02/`를 사용한다. v0.1을 복사해 수정하더라도 원본은 변경하지 않는다.
2. codec 복원·오염 거부 → 후보 묶음/기존 출력 대조 → 끝점·재개·잠금·통계의 회귀 검사를 통과한다.
3. 새 기술 검증에서 짧은 전체 탐색 경로의 유전체·행동·검증 후보·선발이 v0.1과 같은지 비교하고 추가 호출을 별도로 센다. 본·기존 테스트는 열지 않는다.
4. 새 훈련 전용 예비·추가 비용 표본의 시드·호출 수·전체 작업 목록·중단/재개를 실행 전에 고정한다. 비용 외삽·디스크·메모리 기록을 갱신한다.
5. 동치·비용 게이트를 모두 통과한 경우에만 새 소스·수치 계획을 해시와 Git 커밋으로 잠그고 원래 본 비교로 진행한다. 실패하면 본을 실행하지 않고 실패 원본과 변경 이유를 보존한다.

이 준비 설계가 처리 속도 향상이나 과학적 비교 결과를 보장하지 않는다. 실행을 마친 것으로 보고하지 않는다.
