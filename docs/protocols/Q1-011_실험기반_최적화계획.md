# Q1-011 — 실험 코드와 기록의 최적화 계획

작성일: 2026-10-17. 상태: 실행 전 기술 계획. 사용자가 재사용성·속도·확장성을 종합한 코드 최적화와 정보가 보존되는 로그 축소를 요청했다. 기존 완료 실행은 변경하지 않는다.

## 1. 범위와 평가 기준

새 공통 패키지 `studies/interaction/evosim_runtime_v01/`에 평가·저장 인터페이스를 분리하고, `evosim_q1007_v02/`는 동결된 유전체·유전 연산·지표 정의를 명시적으로 재사용하는 기술 어댑터로 만든다. 과거 완료 패키지는 소스 해시로 검사하고 수정하지 않는다. 모듈 이름만 새로 붙인 전체 복사는 재사용성 개선으로 세지 않는다.

| 축 | 확인할 내용 | 채택 기준 |
|---|---|---|
| 정확성 | 같은 입력·난수 키의 출력·행동·보상·동률·지표·선발·중단/재개 | 바이트/배열의 정확한 일치. 허용 오차만으로 행동 차이를 허용하지 않음 |
| 재사용성 | 저장·평가와 실험의 선발·유전 연산 분리 | 공통 API, 실험 어댑터, 두 평가 경로·일반 JSON 경로에서 사용 확인 |
| 속도 | 후보 단위 평가 대비 집단 묶음 평가, 저장·복원 포함 | 고정 비용 사례3회 중앙값·모든 측정값 보고. 느린 조건도 보존 |

## 2. 구현 순서

1. 순서가 보장된 F0 연산을 후보 축으로 묶는다. 행렬 곱으로 합산 순서를 바꾸지 않고, 동률 시에만 난수 객체를 준비한다. 후보별 난수 키·추첨 이력은 원래와 같다.
2. 평가 결과의 지표·전체 기록 인터페이스를 유지한다. 기존 경로는 일반 구조의 명시적 fallback으로 제공한다. 서로 다른 후보의 상태가 섞이지 않는지 확인한다.
3. 저장은 일반 JSON과 환경별 기록 codec을 분리한다. 공통 에피소드·행동열·유전체를 공유한다. 환경에서 계산할 수 있는 값은 재구성하되 실제 관측값이 다르면 예외값을 함께 저장한다. 보상 계산 오류 같은 증거를 정상 값으로 바꿔 버리지 않는다. 알 수 없는 필드도 보존한다.
4. 환경 코드 해시·schema·내용 해시·원본 전체 내용 해시를 저장한다. 복원/감사는 파일 단위로 동작한다. gzip 강도·인코딩은 명시적인 옵션이고 과거 자료를 소급 변환하지 않는다.
5. 실험 어댑터에서 짧은 훈련 전용 탐색·선발·중단/재개·감사를 연결한다. 실제 본 실행 진입점은 이번 범위에서 만들지 않는다. 본의80시드·과학적 조건·문턱을 바꾸지 않는다.

## 3. 검증과 호출 예산

기술 시드는3101·3102, fixture의 순수 경계/동률 검사 키는 별도로 명시한다. 모든 정책 입력은 훈련 분할만 쓴다. 성능에 따라 유리한 시드만 남기지 않는다. 고정 비교는 집단20/40×훈련24개×1반복과 집단20/40×훈련252개×3반복이다. 원래 경로와 새 경로를 각각3회 측정하여 총280,800정책 에피소드 호출을 사용한다. 실행 순서는 고정 난수로 섞고 기록한다. 각 비교에서 전체 기록·지표가 정확히 같아야 한다.

경계·무작위·동률·조기 종료·벽 반복·목표 변경·구조 fallback과 짧은 탐색을 별도 검증한다. 기준/새 평가의 실제 호출을 각각 계수한다. 검증 fixture 상한100,000호출, 총 기술 호출 상한380,800이다. 상한을 넘길 필요가 생기면 먼저 변경 이유와 새 명세를 기록한다. 기존 Q1-007 원자료의 codec 검사는 새 정책 호출0이다.

저장 측정은 Q1-010의 동일122파일 전체를 사용해 기존gzip3·새 codec을3회 비교한다. 입력 전체 해시·복원 바이트·알 수 없는 필드·고의적인 잘못된 보상/지표의 보존을 확인한다. 임의 최소 용량을 보장하지 않으며, 크기·복원 시간·구현 복잡도의 절충을 근거로 기본값을 선택한다.

## 4. 기록과 판단

새 기술 출력은 `studies/interaction/optimization_q1011_v01/`에 두고 계획·소스 해시·개별 측정·실패·호출 원장을 보존한다. 개발 검사는 본 결과로 세지 않고 호출도 별도 합산한다. 실패한 완료 측정을 덮어쓰지 않고 다음 버전/실행 폴더에서 수정한다. 코드 개발 중 본 측정 전 수정과 고정 후 수정을 구분한다.

최종 보고서에는 좋아진 항목과 남은 한계를 함께 적는다. 새로운 기술 기반의 통과는 Q1-007 본 비용 게이트 통과나 진화 성능 향상을 뜻하지 않는다. 문서 점검 후 명시적으로 선택한 파일만 작업 브랜치에 커밋·push한다.
