# Q1 구현 순서와 검증 기록

문서 유형: 기존 통합 문서의 해당 절을 분리한 설계·구현 기록. 본문 속 예정·미완료 표현은 작성 당시의 상태다. 최종 실행 상태는 [연구 현황](../03_연구현황.md), 실행값은 [고정 프로토콜](../../studies/interaction/evosim_interaction/results_v01/protocol.json)을 따른다.

본문의 `evosim_interaction/` 경로는 이제 `studies/interaction/`을 작업 디렉터리로 삼은 상대 경로다. 후속 진단과 실행 결과는 별도 보고서로 관리한다.

계획 문서는 이 파일 하나를 계속 사용한다. 실제 코드는 새 작업 폴더 `evosim_interaction/`에 둔다. 과거 결과를 만든 `evosim_research/`는 근거로 보존한다. 아래 경로 중 A1~A2는 구현했고 나머지는 예정 구조다.

#### 구현 전에 고정할 인터페이스

- **정책 입력:** 네 관측값과 정책 전용 난수만 전달한다. 정답·미래 목표·환경 객체·보상 함수를 정책에 전달하지 않는다.
- **정책 출력:** 정수 행동 하나. `0=왼쪽`, `1=오른쪽`, `2=수집`으로 고정한다. 범위를 벗어나거나 비정상 수치가 발생하면 조용히 행동을 바꾸지 않고 오류로 기록한다.
- **환경 출력:** 실행기는 관측·보상·종료 여부를 받는다. 위치·목표 목록·실패 원인 등 진단 정보는 기록기만 사용한다. 종료 후 `step()` 호출은 오류로 처리한다.
- **정책 초기화:** 에피소드마다 이전 출력·모듈 상태·흔적을 초기화한다. 목표를 수집할 때마다 초기화하지는 않는다. 에피소드 내 기억을 허용하는 설계와 맞춘다.
- **정책 복제:** 구조·가중치·설정은 무손실 복사하고 실행 상태는 초기화한다. 후보 선발 지표는 별도 기록으로 저장하며 부모 선발 지표를 덮어쓰지 않는다.
- **행동 선택:** 기존 방식의 소프트맥스 확률을 계산하고 최대값과 `math.isclose(rel_tol=1e-9, abs_tol=1e-9)`인 후보에서 전용 난수로 선택한다. 모든 출력은 유한해야 한다. Q값 조회와 탐험 행동 분기는 사용하지 않는다. 기존 실행과 난수 소비 순서가 같다는 주장은 하지 않는다.
- **난수 파생:** 목적·실행 시드·회차·에피소드 ID·반복 번호를 순서가 고정된 JSON 배열로 직렬화하고 SHA-256으로 정수 시드를 만든다. 프로세스마다 변하는 내장 `hash()`를 쓰지 않는다. 진화용 흐름과 평가용 흐름을 분리하고 규칙·유도 방식을 보존한다.

#### 모듈 ID와 교차의 작업 규칙

초기 `m0`~`m3`는 모든 개체가 공유하는 초기 구조의 대응 위치로 정의한다. 모듈의 연산 매개변수가 다를 수 있다는 사실도 기록한다. 추가 모듈은 실행별 단조 증가 발급기를 사용하고, 발생 사건마다 새 번호를 부여한다. 삭제된 번호는 재사용하지 않으며 자손은 상속한 번호를 유지한다. 재개 파일에 다음 발급 번호도 저장한다.

교차에서는 같은 ID를 가진 모듈만 대응 유전자로 취급한다. 첫 부모는 훈련 성적이 높은 부모로 정하고, 동률이면 두 탐색 슬롯의 고정 순서로 결정한다. 첫 부모의 모듈 집합을 바탕으로 공통 모듈 매개변수와 유효한 연결을 조합한다. 두 번째 부모에만 있는 모듈의 처리와 연결 채택 확률은 기존 방식에서 이어받는 부분·달라지는 부분을 설정표로 명시한다. 모든 순회는 정해진 순서로 수행하고, 순방향 그래프의 순환을 거부한다.

이 규칙은 새 연구의 대응 방식이다. 완전한 NEAT 알고리즘을 재현했다거나, 모든 구조적 대응 문제를 해결했다고 표현하지 않는다. 새 ID 체계가 결과에 미치는 영향은 기존 기억 과제와의 비교에서 별도 변경 사항으로 남긴다.

#### 보존할 실행 자료

최소 보존 항목은 전체 설정·데이터 목록·코드 해시, 평가 회차와 개체 ID, 부모·변이 기록, 선택 후보의 무손실 정책, 에피소드 ID·행동·보상·종료 원인, 실제 평가 횟수·행동 수·실행 시간이다. 원자료에서 보고 지표를 다시 계산할 수 있어야 한다.

훈련·선발의 대량 기록은 압축된 행동 목록과 에피소드 요약을 사용하고, 주 보고 후보의 최종 평가에는 전후 상태까지 보존한다. 저장 방식은 예비 실행에서 용량을 확인한다. 진행 체크포인트에는 난수 상태·집단·후보·다음 ID·완료된 평가 범위를 함께 저장한다. 재개할 때 설정이나 코드가 달라지면 같은 실행으로 이어 붙이지 않는다.

**첫 구현 점검 당시의 완료 범위:** A0의 정적 검토와 A1~A2 구현·정합성 검사였다. 이후 A3~A8의 구현·실행으로 이어진 기록은 다음 절에 정리했다.

#### 후속 구현·예비 점검 기록 — A3~A8

사용자는 결론에 도달할 때까지 스스로 문제를 판단하고 실험을 계속하되 모든 기록을 남기도록 요청했다. 사전에 정한 Q1과 진화 탐색 비교를 이번 연구의 결론 범위로 삼는다. 불확실하거나 실패한 결과도 결론으로 남기며, 유리한 수치가 나올 때까지 설정을 반복 변경하지 않는다.

- A3~A5 완료: 입력 네 개를 사용하는 네트워크, 실행별 모듈 ID, 우수 부모 우선 교차, 동결 평가와 관측 35쌍 검사를 구현했다. 네트워크에는 Q테이블·경험 버퍼·학습 호출이 없다. 내부 활성 상태만 에피소드 안에서 바뀐다.
- A6 완료: 진화와 독립 무작위 탐색이 같은 초기 집단·훈련 묶음·후보 평가 기회를 사용하도록 구현했다. 매 회차의 개체 유전체·부모·변이·행동·보상을 압축 JSON으로 보존한다. 중단 후 재개가 연속 실행과 같은 후보·회차 기록을 만드는 테스트가 통과했다.
- A7 완료: 분석기의 판정 규칙을 합성 데이터로 검사했다. 901·902 시드에서 각 방법을 20개체·10회차 실행했으며 선발셋과 본 테스트의 정책 성적을 사용하지 않았다. 출력은 `evosim_interaction/pilot_v01/`, 콘솔 기록은 `pilot_v01_console.log`에 보존했다.
- A8 준비 완료: 실행기는 시작 전에 소스 해시·전체 설정·분할 목록·난수 규칙·판정 규칙을 `protocol.json`과 `datasets.json`으로 기록한다. 본 실행 중 소스나 설정이 바뀌면 같은 실행으로 재개하지 않는다. 최종 평가는 모든 탐색 완료 및 `candidate_lock.json` 저장 후에만 시작한다.

검증 결과는 총 **21개 테스트 통과**다. 개별 실행과 NumPy 묶음 평가를 비교하여 모든 모듈 연산의 출력, 에피소드의 행동·보상·종료, 동률 처리와 에피소드 순서 독립성을 확인했다. NumPy 2.3.5를 사용하며 버전을 프로토콜에 저장한다. 묶음 평가는 계산 방식의 변경이고 탐색 예산이나 판정 기준의 변경은 아니다.

발생한 문제: 첫 전체 테스트 실행에서 Windows 샌드박스 임시 폴더에 접근하지 못해 재개 테스트가 중단됐다. 이는 연구 알고리즘 실패와 구분해 기록한다. 제한 밖에서 같은 명령을 허용받아 재실행했고 21개 테스트가 모두 통과했다. 예비 실행은 작업 폴더 안에서 정상 완료됐다.

예비 실행 소요 시간은 개별 작업당 약 0.6~0.7초였으며, 훈련 10회차만의 시간이다. 본 실행의 선발셋 평가와 기록 저장은 추가된다. 현재 실행 속도로 사전 예산을 유지할 수 있다고 판단했으며, 칸 수·보상·선발 기준·실행량·판정 경계는 바꾸지 않았다. 예비 결과가 낮은 경우도 모두 보존했다.

**예비 점검 당시의 완료 범위:** A1~A8 구현·검증을 마치고 본 시드 10쌍 실행으로 넘어갔다. 본 실험과 사후 진단까지 마친 최종 상태는 8절에 기록했다.
