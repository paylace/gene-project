# Q1-010 — 기존 기록의 저장 효율 측정 계획

작성일: 2026-10-17. 구분: Q1-007 예비 자료를 재사용하는 사후 기술 측정. 정책 성능 실험이 아니다. 이 문서는 측정 전에 작성했다.

## 목적과 대상

[Q1-007 v0.2 준비 계획](Q1-007_v02_저장과평가_준비계획.md)의 저장 부분만 검사한다. 완료한 v0.1 예비 6작업의 120회차 파일과 훈련 분할을 사용한 검증 크기 비용 표본 2파일, 총 122,160에피소드 기록 전체를 대상으로 한다. 새 정책·훈련·검증·테스트 호출은 0이다. 실제 검증/테스트 분할의 성능을 열지 않는다. 기존 코드·자료는 수정하지 않는다.

## 비교 조건

1. 기존 JSON을 gzip 수준3으로 다시 저장한다. 원본과 같은 압축 조건의 대조다.
2. 같은 JSON을 gzip 수준9로 저장한다. 압축 강도만 높이는 대조다.
3. 파일 안에서 공통 에피소드·반복 순서를 한 번 저장하고 유전체를 참조한다. 레코드를 열 목록으로 바꾸되 모든 필드를 유지한다.
4. 3의 구조에서 행동열을 보존하고 보상·진행·충돌·최종 상태를 동결 환경으로 복원한다.
5. 4에서 파일 안의 동일 행동열을 사전 목록과 참조로 저장한다.
6. 5의 고유 행동열을 행동당2비트로 표현하고 길이와 base64 문자열로 JSON에 담는다. base64·사전·참조·해시 비용을 모두 센다.

3~6은 gzip 수준3을 적용한다. 원본의 후보별 지표·동률 수·유전체·계보·순위 등 나머지 내용은 유지한다. 회차 간 공통 사전은 이번에 만들지 않는다. 실패·재개·프로토콜 등 나머지 파일은 그대로 두고 전체 폴더 효과를 계산할 때 포함한다.

## 완전성·측정

변환 전 전체 입력 파일의 크기와 SHA-256, 도구·환경 코드 해시, Python 버전, 비교 순서를 기계 계획에 잠근다. 축소 파일은 원본 전체 JSON의 해시와 자기 내용 해시를 포함한다. 복원은 원본 파일 내용을 조회하지 않고 축소 파일과 동결 환경만 사용한다. 마지막 비교에서만 원본과 대조한다.

성공 조건은 모든 파일의 모든 필드·형식·순서를 보존한 canonical JSON 바이트가 원본 gzip 해제 바이트와 같고, 작업 전후 원본 전체 해시가 같은 것이다. 이는 환경의 과학적 타당성이나 네트워크 출력 자체의 독립 검토가 아니다. gzip 헤더를 포함한 원본 압축 바이트 재현까지 주장하지 않는다.

각 조건을 별도 자식 프로세스에서 3회 측정한다. 순서는 고정 난수7100701로 미리 섞는다. 각 회차 파일 단위로 읽고 쓰고 복원한다. 복원 시 같은 파일 안에서 같은 초기 조건·행동열의 결과를 메모리에 재사용한다. 최대 메모리는 비교를 위한 원본·복원본을 함께 들고 있는 자식 프로세스의 최대 working set이다. 운영체제 파일 캐시는 통제하지 않는다.

실제 파일 바이트, 압축 해제 바이트, 변환·저장 시간, 읽기·복원·해시·원본 일치 확인 시간, 최대 메모리를 기록한다. 시간은3회 중앙값과 각 실행값을 보존한다. 파일 논리 크기와 파일시스템 할당 크기를 구분하며 이번 물리 지표는 파일 내용 바이트다. 원본 읽기 시간은 변환 시간과 별도 계수한다. 훈련 회차와 비용 표본을 나누고 폴더 전체 효과도 보고한다.

기존 비용 판정을 소급 변경하지 않는다. 본 규모 외삽은 한다면 기술적 추정으로만 표시하고, 전체 탐색 시간 통과나 v0.2 채택으로 해석하지 않는다. 축소율이 높아도 복원 비용이 커지면 절충안을 제안한다. 새 형식을 본 실행에 통합하지 않는다.

## 보존과 재현

도구: `tools/measure_q1007_storage.py`. 출력: `studies/interaction/storage_q1007_v01/`. 기존 출력 폴더가 있으면 중단한다. 도구 자체 검사 뒤 전체 측정을 수행하고, 실패 시 기존 출력은 보존한 채 새 버전으로 고친다. 기계 계획·개별 측정·요약을 보존한다. 변환 사본은 원본과 별도이며 기존 자료를 삭제하지 않는다.
